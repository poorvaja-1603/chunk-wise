Core Recipe: Rabin Content-Defined Chunking (CDC) Formula

Algorithm

Unlike naive fixed-size chunking where inserting 1 byte shifts every downstream chunk boundary, Content-Defined Chunking (CDC) determines chunk boundaries based on content fingerprints calculated over a 48-byte rolling window.

Boundary Trigger Condition:
size >= MAX_SIZE or (size >= MIN_SIZE and (fingerprint & 8191) == 0)
Min Chunk Size 2 KB Prevents tiny chunks
Target Average 8 KB Mask: 0x1FFF (8191)
Max Chunk Size 64 KB Caps chunk size
Rolling Window 48 Bytes Rabin polynomial

Recipe: Post-Deduplication Compression Pipeline

Architecture

Golden Rule: The SHA-256 chunk digest is always computed on the raw, uncompressed bytes before querying DynamoDB. Deduplication must be based on content identity, not format.

1. Chunk Stream: Rabin CDC yields byte slice B.
2. SHA-256 Digest: Compute hash = sha256(B).
3. Deduplication Lookup: Check DynamoDB index for hash.
    ↳ If exists: Increment reference count in DynamoDB. Zero S3 PUT operations performed.
    ↳ If new: Evaluate compression policy (Balanced / Space Saver / Fast Restore).
4. Adaptive Compression: Calculate saved = 1 - (len(zlib(B)) / len(B)).
    ↳ If saved >= threshold: Store compressed bytes in S3 (codec = "zlib").
    ↳ Else: Store raw bytes in S3 (codec = "none").

Recipe: Using the ChunkWise REST API

REST API

Execute HTTP requests from your terminal or CI/CD pipelines to interact with ChunkWise:

1. Upload a File (Idempotent): 
curl -X POST http://127.0.0.1:8080/api/files \
  -H "Content-Type: application/octet-stream" \
  -H "X-File-Name: quarterly_backup.tar" \
  -H "X-Chunker: cdc" \
  -H "Idempotency-Key: job-99812-run-1" \
  --data-binary @quarterly_backup.tar
2. Query Chunk Manifest & Compression Codecs: 
curl -s http://127.0.0.1:8080/api/files/f-123456789abc/chunks | jq .
3. Cryptographically Verify File Integrity: 
curl -X POST http://127.0.0.1:8080/api/files/f-123456789abc/verify
4. Download / Restore File: 
curl -O -J http://127.0.0.1:8080/api/files/f-123456789abc/download

Recipe: Python SDK Integration

Python SDK

Embed ChunkWise directly into your Python data processing pipelines: 

from chunkwise import Engine

# Initialize storage engine (reads AWS or local config from .env)
with Engine("./.chunkwise") as engine:
    # 1. Deduplicate and upload file
    result = engine.put_path("demo_files/report_v1.txt", chunker="cdc")
    print(f"File ID: {result.file_id}")
    print(f"Total Chunks: {result.chunks}, New Chunks Stored: {result.new_chunks}")
    
    # 2. Re-upload identical or edited version to test deduplication
    result_dup = engine.put_path("demo_files/report_v1_duplicate.txt", chunker="cdc")
    print(f"Duplicate chunks avoided: {result_dup.chunks - result_dup.new_chunks}")
    
    # 3. Retrieve system-wide stats
    stats = engine.stats()
    print(f"Deduplication Ratio: {stats.dedup_ratio:.2f}x ({stats.storage_saved_pct:.1f}% space saved)")
    
    # 4. Restore file and verify SHA-256 integrity
    restored_bytes = engine.get_bytes(result.file_id)
    assert len(restored_bytes) == result.size

Recipe: Windows Reparse Points & Symlink Safety

Security

Windows NTFS supports reparse points (symbolic links, directory junctions, and volume mount points). ChunkWise enforces safe traversal:

  • Pre-traversal Inspection: Uses os.lstat() and checks stat.FILE_ATTRIBUTE_REPARSE_POINT prior to descending.
  • Infinite Recursion Prevention: Directory junctions pointing to parent directories are never followed automatically.
  • Metadata Only: Target paths, link types, and relative flags are recorded without storing redundant target data.
  • Path Traversal Guard: On restore, relative link targets attempting to escape the restore directory via ../../ are rejected.
